# Change record: bcftools 1.23.1 to 1.24

Date: 2026-10-19. Branch: `feature/bcftools-1.24`. Decision: adopt for v1.1.0.

## Change

`workflow/envs/bcftools.yaml`: `bcftools=1.23.1` to `bcftools=1.24` (released
2026-07-09). This environment runs `call_bcftools` and also `gather_calls`,
`normalise` and the ClinVar rules for both callers, so the upgrade touches
every caller's output. The FreeBayes environment keeps bcftools 1.21.

## Evidence

Both runs: HG002 full-size data, `profiles/local`, `--forceall`, same host.

| Check | 1.23.1 (v1.0.0) | 1.24 |
| --- | --- | --- |
| `accuracy.tsv`, all 24 rows (both callers, 6 strata, SNV and indel) | baseline | identical (`diff` empty) |
| call_bcftools wall, 8 chunks summed | 20.1 s | 20.2 s |
| call_bcftools peak RSS | 185 MB | 184 MB |
| End-to-end wall | 212.25 s | 212.63 s |
| Test profile plus `tools/check_accuracy.py` | pass | pass |

The normalised VCF header reads `##bcftoolsVersion=1.24+htslib-1.24`.

## Decision

Adopt: no accuracy or resource change on this data, and staying within one
release of upstream keeps later upgrades small.

## Rollback

1. `git revert` the commit that changed `workflow/envs/bcftools.yaml`.
2. Rerun from the first affected rule; Snakemake's software-environment
   trigger reruns `call_bcftools`, `gather_calls`, `normalise` and everything
   downstream: `.venv/bin/python tools/snakemake_macos.py --profile profiles/local`.
3. Optionally delete the unused environment under `.snakemake/conda/` (the
   folder whose `.yaml` pins bcftools 1.24) with `snakemake --conda-cleanup-envs`.
4. Confirm `results/report/accuracy.tsv` matches `docs/validation.md`.
